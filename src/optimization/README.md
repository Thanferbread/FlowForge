# 布局搜索模块

真实实现入口为 `optimizeLayout(scene, config, options)`，类型见 `types.ts`。通过 `AbortSignal` 取消，以 `onProgress` 获取进度；每 1–10 tick 让出事件循环（默认 10）。结果状态为 `accepted / no-improvement / cancelled / failed`。调用方在异步返回后仍需核对当前任务 ID/场景版本，避免已切换场景接收旧任务。

- 候选只整体正交平移一个展位的实体、服务格、队列 1–3 格。入口、出口、墙、展位 ID、服务容量、服务时长范围与外生需求不变。完整静态校验通过才运行。
- 固定训练种子 11/29/47，固定留出 83/101。每个种子在原场景先生成需求，再注入各候选，保存配对需求哈希。训练按系统完成率→截尾耗时→拥堵暴露排序；同分保留基线；只有训练首位可接触留出。
- 留出要求每颗种子离场人数非降，并满足预设 1 个百分点/1 秒门槛；失败回退原布局。等待均值只描述已开始服务者，不能作为忽略未完成人员的主目标。详细规则同时存在结果对象内。
- 默认 8 个候选，最多 12 个；H≤300、人数≤180、地图≤1600格、展位≤12。默认最多 33 次完整运行，最大候选预算时最多 45 次。缓存可降低实际运行数。保存真实计数、拒绝原因和失败，不保留逐 tick 大体积轨迹。
- `preview.before/after` 是 UI 种子下的原布局/最终选定布局。`preview.proposed/proposedScene` 是训练优胜候选，即使未通过留出也可展示；必须标明“训练候选（未采用）”。它不影响选优。未采纳时 after 与 before 相同。
