# 码道开发过程

FlowForge 从校园招聘会的场地需求起步，用华为云码道逐阶段建立编辑器、仿真主体与初版平滑动画，再结合实际运行反馈完善作品。

## 需求与方案

把地图尺寸、障碍、出入口、展位与队列等约束写入需求规格，再生成实现方案和任务清单。这样可以对照同一套术语讨论界面和引擎，分阶段检查交付，而不只依赖一次长对话。

## 场景编辑

第一阶段产出 React + Vite + TypeScript 工程与Canvas编辑界面。码道完成地图操作、逐入口通路校验、障碍连续拖涂、展位包整体编辑及JSON导入导出，让地图成为后续仿真的可运行输入。

## 仿真主体

第二阶段实现种子需求、路径搜索、人员状态、排队服务、单步推进与指标展示。运行控制连接同一引擎，支持运行、暂停、单步、取消、重置和报告导出，逐步把规格转成可观察的行为。

## 动画迭代

在已有引擎上增加纯显示插值模块和分层Canvas。相邻格心之间连续绘制，模型仍按离散时间步提交。码道阶段交付记录为23个测试文件、286项通过，保留对应原始输出。

## 验收与后续完善

根据真实使用反馈复核规格、检查状态和报告，再完成后续修复及布局分析等扩展。最终整体回归为26文件324项通过。过程展示保留码道的需求、任务、文件改动与交付截图；各阶段的实际协作范围见 [开发分工](CONTRIBUTIONS.md)。

本地完整交付包中的码道使用证明按阶段整理原始截图，产品界面与开发记录分别展示。
